# Объединение CNC-проектов

Основной репозиторий — `cnc-assistant`. Отдельное развитие `cnc_ai_ecosystem` прекращено: его проверенная базовая NLP-логика перенесена в `cnc_ml/`.

## Что сравнивалось

Прочитаны обе API-точки входа (`app/main.py` и `api/main.py`), маршрутизация намерений, экспорт обучающих данных и ML-компоненты. Сравнивались функции, зависимости и способ запуска. Общая предметная область не означает, что исходники можно заменить друг другом целиком.

| Задача | Что оставлено в основном проекте |
|---|---|
| Telegram, CLI, инженерные расчёты, стандарты | Существующая реализация `cnc-assistant` |
| TF-IDF + LinearSVC | Отдельный обучаемый baseline в `cnc_ml/intent_classifier.py` |
| Карта классов и валидация обучающего входа | Перенесены из `ml_core/label_mapping.py` и усилены проверкой типов |
| Оценка NER | Переработана: учитываются номер документа, тип и обе границы сущности |
| Второй HTTP API, JWT и фиктивная БД | Не включены в основной сервис |
| Transformers, retrieval, crawlers и Celery-прототипы | Остались в исходном репозитории и полной локальной Git-копии; не интегрированы |

Исходная версия NLP-контрактов: [cnc_ai_ecosystem, commit 41c97e9](https://github.com/DmitriiKonovalovLull/cnc_ai_ecosystem/commit/41c97e9c0f27e6c6aba106d3e2660271943ff957).

## Почему не перенесён весь второй API

В `api/dependencies.py` прежнего проекта `get_db` возвращает `AsyncSessionStub`. При недоступности JWT или настроек, а также при ошибке JWT, аутентификация возвращает пользователя с `is_superuser=True`. Такой API нельзя подключать к основному приложению как готовую замену.

В исходной NER-оценке сущности разных документов объединялись в один набор, а конечная граница не участвовала в сравнении. Новый evaluator исправляет оба случая. Заготовка token accuracy не переносилась как работающая метрика.

## Использование перенесённого блока

`cnc_ml` — опциональный исследовательский модуль с собственным CLI. Telegram-бот не переключён на обученную модель: для этого нужны реальные данные и проверка совместимости её классов с существующей маршрутизацией.

Это выборочное объединение проверяемой логики, а не перенос всего прототипа. Исходный код остальных экспериментов сохранён, поэтому к ним можно вернуться отдельно. Пароли, локальные базы, пользовательские контексты и журналы в новый модуль не переносились.

Тесты нового блока обучают настоящий sklearn pipeline на синтетических данных, проверяют сохранение/загрузку, CLI, стабильность меток и отсутствие обучения векторизатора на validation-текстах. Они не измеряют качество на реальных CNC-запросах и не проверяют весь бот.
